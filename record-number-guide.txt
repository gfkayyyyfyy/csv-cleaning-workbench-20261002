trim 流程的记录定位说明：空行、空字段与引号内换行（csv_cleaner.py）
=====================================================================

本文依据仓库根目录当前版本的 csv_cleaner.py，专门解释 --rule trim 一条
线上“报错里的 record 指向哪条记录”：CSV 怎样被解析成记录、记录序号如何
编号、列数校验在哪一步发生、单元格何时被 trim、结果何时写出，以及空行、
空字段、引号内换行如何影响定位。结论先行：错误信息和 changes 里的
record 是 CSV 记录序号（表头记为 1），不是文本编辑器里的物理行号；引号
内换行会占用物理行但不增加记录，引号外的空行则是一条独立记录。文中行号
对应 csv_cleaner.py 当前源码。本次只新增本文这一份说明，程序、命令行参
数、摘要 JSON 结构与既有文档均未改动。

一、一条记录是怎样编号的：read_records() 与 enumerate(start=1)
----------------------------------------------------------------

* 读取只发生在 read_records()（第 337-357 行）。第 346 行以
  encoding="utf-8-sig"、newline="" 只读打开输入（容忍一个 UTF-8 BOM，
  且不修改输入），第 347 行用
  `csv.reader(infile, delimiter=delimiter, strict=True)` 按显式分隔符
  解析——分隔符来自 --delimiter（默认逗号，见第 126-127 行与第 367
  行），从不根据文件内容猜测；strict=True 意味着引号不成对等 CSV 语法
  错误会抛 csv.Error，由第 351-352 行捕获并经 fail() 以退出码 2 失败
  （UTF-8 解码失败与读取失败分别在第 353-354、355-356 行处理）。
* 记录序号在第 349 行
  `for record_no, record in enumerate(reader, start=1)` 从 1 开始计
  数。函数文档字符串（第 338-343 行）写明：表头是第 1 条记录；引号内
  换行不推进这个序号。read_records() 返回的是
  (record_number, fields) 元组列表，此后所有环节都只用这个
  record_number，再也接触不到物理行号。
* 所以“物理行”和“记录”是两层东西：字段被双引号包住后，里面的真实
  换行只是该字段的字符，csv.reader 要读到闭合引号之后的记录结束符才
  结束这条记录——一条记录可以横跨多个物理行，record_no 却只加一次。
  反过来，引号外的换行结束当前记录；文件末尾那个正常换行只是最后一条
  记录的结束符，不会再产生一条空记录（见第八节边界一）。

二、从解析、列数校验、单元格清理到输出的先后顺序
--------------------------------------------------

main()（第 360-501 行；第 504-505 行只是脚本入口调用）的顺序决定了哪类错误先报、摘要要到什么时候才可
能打印：

1. 参数与规则（第 361-421 行）。trim 在 RULES 中直接绑定为 str.strip
   （第 251-256 行，trim 项在第 252 行），不含任何额外包装；--rule 取
   值不支持在第 379-382 行拒绝。
2. 输出路径两项检查（第 423-426 行）：不能与输入指向同一路径（第
   423-424 行）、输出路径不能已存在（第 425-426 行）。--dry-run 并不
   豁免这两项。
3. 读入全部记录（第 428 行调用 read_records）。
4. 表头校验（第 430-439 行）：没有记录或第一条记录没有字段，在第
   430-431 行报 `input is empty: no header record`；表头含空列名
   （第 433-434 行）、表头重名（第 435-436 行）、找不到目标列（第
   437-438 行）各有专属报错；目标列下标 column_index 在第 439 行确
   定。
5. 逐条数据循环（第 447-480 行）。expected_fields 取表头列数（第 441
   行）。每条记录先在第 448-450 行做列数校验，不符立即
   `fail(f"record {record_no} has {len(record)} field(s), expected "
   f"{expected_fields}")` 退出 2——这一步发生在任何单元格清理之前。
   校验通过后，第 452 行只取目标列原值 original，第 466 行
   `cleaned = rule(original)`（trim 时即 str.strip）；第 470 行比较
   清洗前后，不同才在第 471-476 行追加 changes、第 477 行写回本列、
   第 478 行让 changed_cells 加一。非目标列自始至终不参与。
6. 写出结果（第 482-494 行）：仅当不是 --dry-run。第 484 行用 "x"
   独占新建模式打开输出（encoding="utf-8"、newline=""，无 BOM），第
   485-486 行 `csv.writer(outfile, delimiter=output_delimiter)
   .writerows(out_rows)` 写出全部行。
7. 打印摘要（第 496-501 行）：summary 先放 rows、changed_cells（第
   496 行），加了 --include-changes（参数定义在第 319-322 行）才在第
   499-500 行附加 changes 数组，最后第 501 行 print(json.dumps
   (summary))。

关键推论：列数错误在第 449 行经 fail()（第 259-261 行：向 stderr 打印
`error: ...` 后 sys.exit(2)）直接终止，永远到不了第 501 行。所以即便
出错记录之前已经存在可清理的值，也不会得到“前半截”摘要，真实导出时
更到不了第 482 行的写出块——标准输出为空，也没有半成品文件。

三、空行、空字段、引号内换行：四种长相，四种字段数
------------------------------------------------------

csv.reader 按“分隔符切出了几个字段”计数，并不看物理行是否空白：

* 引号外空行（且不是文件末尾那个结束换行）：切不出任何字段，是一条 0
  字段记录（本文第七节的 record 5 即属此类）。
* 独立的纯空格行：空格是未加引号字段里的普通字符，整行就是一个含若干
  空格的字段，即 1 字段记录；在双列表头下因列数不符退出 2。
* 单独一个逗号 `,`：分隔符在左右各切出一个字段，两个字段都是空字符
  串，即 2 字段记录，列数与表头一致，合法。空“字段”与零字段的“空
  行”是两回事：数据行允许有空字段（只有表头不允许有空列名，第 433-
  434 行）。
* 引号内换行（连同引号内的空行）：换行被双引号保护，属于该字段解析值
  的一部分，既不结束记录也不产生空记录；物理行变多、记录不增多。

四、成功样例输入 records.csv
-----------------------------

在项目根目录把以下内容原样保存为 UTF-8 编码的 records.csv（默认逗号分
隔；每个物理行末尾为一个 LF，最后一行 `"   ",` 之后也有一个正常的末尾
换行；当前目录若已有同名 records.csv，请先备份或换到空目录）。注意第
三个物理行是整行没有任何字符的空行，且它位于一对双引号之内：

    name,note
    " Alice ","line one

    line three"
    ,ok
    "   ",

物理行与 CSV 记录的对应关系如下（这正是“record 不等于编辑器行号”的
样子）：

  物理行 1  name,note                    记录 1（表头，2 字段）
  物理行 2  " Alice ","line one          记录 2 开始
  物理行 3  （整行为空，位于引号内）     仍属于记录 2 的 note 字段
  物理行 4  line three"                 记录 2 结束（note 的引号闭合）
  物理行 5  ,ok                         记录 3
  物理行 6  "   ",                      记录 4（行尾 LF 仅结束本记录）

文件有 6 个物理行，却只有 4 条记录。三条数据记录解析后的值为：

* 记录 2：name 为两端各一个 ASCII 空格的 ` Alice `；note 为
  `line one` 与 `line three` 之间夹着连续两个真实换行
  （"line one\n\nline three"），那两个 LF 一个结束物理行 2、一个构成
  空的物理行 3，但都在引号内。
* 记录 3（物理行 5，`,ok`）：name 为空字符串；note 为 `ok`。
* 记录 4（物理行 6，`"   ",`）：name 为三个 ASCII 空格；note 为空字
  符串。

五、导出命令与预期摘要
------------------------

从项目根目录执行（清理 name 列并开启 --include-changes，输出到尚不存
在的 cleaned.csv）：

    python csv_cleaner.py --input records.csv --output cleaned.csv --column name --rule trim --include-changes

结果：退出码 0，标准错误为空，标准输出只有一行 JSON 对象：

    {"rows": 3, "changed_cells": 2, "changes": [{"record": 2, "column": "name", "before": " Alice ", "after": "Alice"}, {"record": 4, "column": "name", "before": "   ", "after": ""}]}

核对要点：

* rows 为 3，即三条数据记录（不含表头）；changed_cells 为 2。
* changes 按记录顺序只含记录 2 和记录 4，column 均为 "name"。记录 2
  的 before 保留两端各一个空格（" Alice "），after 为 "Alice"；记录 4
  的 before 保留三个 ASCII 空格（"   "），after 为空字符串。before 是
  解析后的原字符串，空白不预先规范化（第 452、471-476 行）。
* 记录 3 的 name 本就是空字符串，str.strip 后仍为空字符串，第 470 行
  比较为假，不收录；note 列从不处理。引号内那两个换行因此完全不影响
  记录序号——报错或明细中若出现记录 4，指的是物理行 6 那条数据。

六、导出文本 cleaned.csv
-------------------------

cleaned.csv 被创建，完整内容如下（记录之间的行尾实际为 CR+LF，这是
csv.writer 的默认行终止符；记录 2 备注引号内的两个换行保持为两个真实
LF，不被改写；文件为无 BOM 的 UTF-8）。其中第三物理行同样是引号内的
空行，整行无字符：

    name,note
    Alice,"line one

    line three"
    ,ok
    ,

核对要点：

* 表头仍为 name,note，记录顺序不变。记录 2 的 name 去掉两端空格后不
  再需要引号，写作 Alice；其 note 因含真实换行，写出时由 csv.writer
  自动加双引号保护，解析值仍是 line one 与 line three 之间两个真实换
  行。记录 3 仍是 `,ok`（name 空、note 为 ok）。记录 4 的 name 由三
  个空格变为空字符串，note 本就为空，整行写作单独一个逗号 `,`（两个
  有效空字段，不是 0 字段的空行）。
* 三条备注的解析内容不变：记录 2 的两个真实换行、记录 3 的 ok、记录 4
  的空字符串均与输入一致；变化只发生在 name 列。
* 输入 records.csv 以只读方式打开（第 346 行），导出后其字节保持原
  样；输出为无 BOM 的 UTF-8（第 484 行 encoding="utf-8"）。

七、失败样例：正常末尾换行之后再加一个引号外空行
---------------------------------------------------

把 records.csv 原样保留，在其末尾那个正常换行之后再追加一个空行（即再
多写一个 LF，且该空行在任何引号之外），另存为 records_bad.csv。于是文
件多出物理行 7（整行为空、引号外），它被解析成记录 5，一条 0 字段记
录；前面的记录 1-4 与成功样例完全相同，其中记录 2、4 的 name 仍然是可
清理的值。

约定项目根目录下不存在 missing 目录，执行一次 --dry-run（输出路径
missing/preview.csv 尚不存在且与输入不同）：

    python csv_cleaner.py --input records_bad.csv --output missing/preview.csv --column name --rule trim --include-changes --dry-run

结果：退出码 2，标准输出为空，标准错误恰好为下面一行：

    error: record 5 has 0 field(s), expected 2

核对要点：

* 报错中的 5 是记录序号（表头记 1，物理行 7 那条引号外空行是记录
  5），不是把引号内换行也算进行号得到的物理行号；列数校验在第 448-
  450 行、expected_fields 为表头列数 2（第 441 行）。
* 不创建任何文件或目录：运行后 missing 目录仍不存在，preview.csv 未
  生成。--dry-run 本来就跳过第 482-494 行的写出块；而列数失败发生在
  更早的第 449 行。
* 不产生部分摘要：尽管记录 2、4 已有可清理的 name，第 449 行 fail()
  直接退出，第 496-501 行的摘要组装与打印不会执行，所以标准输出为空，
  而不是先给出半截 changes。records_bad.csv 字节不变。

八、边界汇总
--------------

一、正常末尾换行不增加记录。records.csv 最后一行 `"   ",` 后的那个 LF
    只是记录 4 的结束符，解析结果是 4 条记录、rows 为 3；要再出现一个
    引号外空行才会多出记录 5（第七节）。

二、引号内空行（引号内换行）属于字段。它占用物理行、出现在该字段的解
    析值里，但不推进记录序号，也不触发列数错误；闭合引号后记录才结
    束。strict=True（第 347 行）下引号必须正确配对，否则按 CSV 解析错
    误在第 351-352 行失败，那是另一类错误。

三、单独的逗号表示两个有效空字段。`,` 解析为两个空字符串，列数与双列
    表头一致，是合法数据行（实测 `name,note` 表头加一行 `,` 时预览退
    出 0，rows 为 1、changed_cells 为 0）。数据单元格允许为空；只有表
    头位置的空列名才被第 433-434 行拒绝。

四、独立的纯空格行只有一个字段。例如 `name,note` 表头、一条正常记录后
    再单独一行三个空格，该行解析为仅含 "   " 的 1 字段记录，在双列表头
    下按列数不符退出 2，标准错误为
    `error: record 3 has 1 field(s), expected 2`——空格是字段内容，不
    会把这行“算成空白而忽略”。

五、首个物理行就在引号外为空时，它就是第 1 条记录（表头）且字段数为
    0，第 430-431 行据此失败，标准错误为
    `error: input is empty: no header record`。程序不会跳过这条空记录
    去后面寻找真正的表头；空文件（零字节）同样落到这一检查。

六、--dry-run 与真实导出在输入校验上行为相同。读取（第 428 行）、表头
    校验（第 430-439 行）和逐记录列数校验循环（第 447-480 行）都在
    `if not args.dry_run:`（第 482 行）之前，与是否预览无关。因此对
    records_bad.csv 去掉 --dry-run 做真实导出，得到的退出码 2、空标准
    输出与同一行标准错误完全一致，且同样不生成文件或目录；两种模式唯一
    的差别只是校验全部通过后是否执行第 482-494 行的写出。

九、源码位置核对清单
----------------------

* 记录读取与序号：read_records() 第 337-357 行；只读打开第 346 行；
  csv.reader(..., strict=True) 第 347 行；enumerate(reader, start=1)
  第 349 行；CSV/UTF-8/IO 失败第 351-356 行。
* trim 规则：RULES 第 251-256 行（"trim": str.strip 在第 252 行）；
  取值与绑定第 379-382 行；调用 rule(original) 第 466 行。
* 表头与列数：空表头第 430-431 行；空列名第 433-434 行；重名第 435-
  436 行；列不存在第 437-438 行；expected_fields 第 441 行；逐记录列
  数报错第 448-450 行。
* 单元格比较与明细：取目标列第 452 行；前后比较第 470 行；changes 追
  加第 471-476 行；changed_cells 第 478 行。
* 输出与摘要：写出块第 482-494 行（"x" 新建第 484 行，writerows 第
  485-486 行）；--dry-run 定义第 330-333 行；--include-changes 定义
  第 319-322 行；summary 组装与打印第 496-501 行。
* 失败出口：fail() 第 259-261 行（stderr 打印 `error: ...` 后
  sys.exit(2)）。
