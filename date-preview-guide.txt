日期预览与导出说明（csv_cleaner.py）
=====================================

本文说明 csv_cleaner.py 的 normalize-date 规则在“只预览”（--dry-run）与
“导出”两种用法下的行为与关系。文中行号对应仓库根目录的 csv_cleaner.py。

一、日期处理与写出开关的关系
----------------------------

日期规范化逻辑与是否写出文件是两个独立的开关：

* 日期处理由 --rule normalize-date 与 --date-order 决定，实现见
  csv_cleaner.py 的 normalize_date()（第 140-189 行）。接受四种写法：
  YYYY-MM-DD、YYYY/MM/DD、YYYY.MM.DD 与年末斜杠日期 NN/NN/YYYY。年末
  斜杠日期的解释完全由 --date-order 决定：mdy 读作 MM/DD/YYYY，dmy
  （缺省）读作 DD/MM/YYYY，歧义值按所选顺序确定，不猜测、不回退；
  YYYY-MM-DD、YYYY/MM/DD 与 YYYY.MM.DD 在两种顺序下都按年月日处理。
  YYYY.MM.DD 要求两个英文句点、ASCII 数字、四位年份与两位月日
  （DATE_DOT_RE，第 94 行；匹配分支在第 172-174 行），没有“年份在末尾”
  的点写法，03.02.2024 之类一律非法。非法日期抛出 InvalidDateError，
  主流程在第 373-377 行捕获后报错退出。
* --dry-run（参数定义在第 268-271 行）只控制最后的写出步骤：第 390 行
  `if not args.dry_run:` 之内的代码才会以 "x" 模式创建输出文件
  （第 392-393 行，UTF-8、无 BOM）。预览模式下该整块被跳过，因此预览
  不会创建输出文件，也不会创建缺失的父目录。
* 两种模式共享同一条读取、校验与统计路径：输入解析见 read_records()
  （第 275-295 行），记录序号从表头 1 开始，带引号字段内的真实换行不会
  推进记录序号；摘要 JSON 的打印在第 403-406 行，两种模式完全一致。
  因此预览摘要中的 rows、changed_cells、changes 就是同参数导出时会
  发生的变化，但预览本身不产生任何文件。

预览为何不保证目标位置可写：--dry-run 只做“路径形参”检查（输出不能与
输入相同、输出文件不能已存在，第 345-348 行），从不触碰文件系统目标。
父目录是否存在、目录是否可写、磁盘是否有空间，预览一概不验证；缺失的
父目录不会阻止一次有效预览。所以预览成功只说明“输入合法、规则可应用、
路径形参不冲突”，不代表真实导出一定成功；反之，导出时的写入失败
（第 394-401 行）只有去掉 --dry-run 后才会暴露。请区分日期校验与文件
写入：预览摘要是变更报告，不是文件已生成的凭证。

二、样例输入
------------

将以下内容原样保存为 UTF-8 编码的 dates.csv（第一条备注的引号内包含
一个真实换行；若当前目录已有同名 dates.csv，请先备份或换到空目录）：

    due_date,note
    05/06/2024,"line one
    line two"
    2024/02/29,leap day
    2024-01-01,new year
    ,empty date

四种写法可在同一列混用；把任意一条换成点写法（例如 2024.02.29、
0001.01.01）规则同样适用，结果统一写成 YYYY-MM-DD，且点写法的解释
不受下面 --date-order mdy 影响。

三、预览（不写出任何文件）
--------------------------

约定 missing 目录不存在。执行：

    python csv_cleaner.py --input dates.csv --output missing/preview.csv --column due_date --rule normalize-date --date-order mdy --include-changes --dry-run

结果：退出码 0，标准错误为空，标准输出只有一个 JSON 对象：

    {"rows": 4, "changed_cells": 2, "changes": [{"record": 2, "column": "due_date", "before": "05/06/2024", "after": "2024-05-06"}, {"record": 3, "column": "due_date", "before": "2024/02/29", "after": "2024-02-29"}]}

要点：

* rows 为 4，changed_cells 为 2；changes 按记录顺序只列记录 2、3，
  before 保留原值，after 分别为 2024-05-06（mdy 解释 05/06/2024）与
  2024-02-29（YYYY/MM/DD 与 --date-order 无关；YYYY.MM.DD 同样无关）。
  已是标准形的 2024-01-01 与空字符串不产生变化。
* 点写法按年月日解释：2024.02.29 变为 2024-02-29，0001.01.01 变为
  0001-01-01；两端空白先按 str.strip 去除（" 2024.02.29 " 合法），
  而未补零月日（2024.2.29）、混用分隔符（2024-02.29）、年末点写法
  （01.02.2024）、全角数字或全角句点、时间后缀等均为非法日期。
* 带引号备注里的真实换行仍属记录 2，不会把后续记录的序号顶大。
* missing 目录依旧不存在，preview.csv 未创建，dates.csv 未被修改。

四、导出（真实写出）
--------------------

移除 --dry-run，输出改为当前目录的新文件 exported.csv：

    python csv_cleaner.py --input dates.csv --output exported.csv --column due_date --rule normalize-date --date-order mdy --include-changes

结果：退出码 0，标准错误为空，标准输出是与预览完全相同的 JSON 摘要。
exported.csv 被创建，保留表头、记录顺序和全部备注（含第一条备注中
引号内的换行），仅 due_date 列的两处被规范化；文件为无 BOM 的 UTF-8。
输入 dates.csv 保持原样。

五、失败示例：非法日期
----------------------

把样例中第二条日期改成 13/02/2024、第三条改成 02/30/2024（即记录 3、4
的 due_date），再次执行上面的 mdy 预览命令：

    python csv_cleaner.py --input dates.csv --output missing/preview.csv --column due_date --rule normalize-date --date-order mdy --include-changes --dry-run

结果：退出码 2，标准输出为空，标准错误为：

    error: invalid date in column 'due_date' at record 3: '13/02/2024'

要点：

* mdy 下 13/02/2024 是月份 13，非法；校验按记录顺序在遇到第一个非法
  日期时即停止（第 373-377 行），因此后面的 02/30/2024（2 月 30 日，
  同样非法）不会被报告。点写法同理：例如把第二条数据记录改成
  2023.02.29（2023 年非闰年），它位于记录 3，报错为
  `error: invalid date in column 'due_date' at record 3: '2023.02.29'`，
  原值原样出现在诊断信息中。
* 备注中的引号内换行不增加记录序号，出错位置仍是记录 3。
* 不创建任何输出文件或目录，输入保持不变。导出模式（去掉 --dry-run）
  下同一输入的报错与退出码相同，因为日期校验发生在写出之前。

六、失败示例：路径冲突（预览同样拒绝）
--------------------------------------

--dry-run 不免除路径形参检查（第 345-348 行在写出分支之前执行）：

* 输出与输入相同：

      python csv_cleaner.py --input dates.csv --output dates.csv --column due_date --rule normalize-date --date-order mdy --dry-run

  退出码 2，标准输出为空，标准错误：

      error: output path must be different from the input path

* 输出指向已存在的文件（先成功导出过 exported.csv）：

      python csv_cleaner.py --input dates.csv --output exported.csv --column due_date --rule normalize-date --date-order mdy --dry-run

  退出码 2，标准输出为空，标准错误：

      error: output file already exists: 'exported.csv'

两种情况下原文件（输入与已存在的输出）都保持不变。而缺失的输出父目录
（如第三节的 missing/）不阻止有效预览——它只会在真实导出时导致写入
失败。
